0.9.2-special — design

One special agent per run that can run on a different parameter set than the crowd — edited in a dedicated Special… modal (same chrome pattern as Advanced / Help). Marking is secondary; the point is a live A/B body inside one world.

1. Opinion — you’re right

Pin already solves “follow one agent.” A special that is only a gold ring + auto-pin would be redundant chrome. The interesting 0.9.2 is: one agent with its own knobs, so you can watch “greedy seeker vs crowd,” “slow wanderer in a Seek world,” “glass-cannon hunger,” etc. in a single run.

Why different params is the right slice

  • Real experiment value — same map, same food, different body rules.
  • Bridge to Phase 1 — one heterogeneous agent before full trait distributions.
  • Modal fits the product — Advanced is world/eat; Special is this one agent; keeps the left rail clean.
  • Pin still useful — pin the special (or anyone) for trends; roles stay clear.

What to be careful about

  • Don’t rebuild Phase 1 — not N random trait draws; just one override profile.
  • World vs agent knobs — food spawn, agent count stay global; special doesn’t get a private food rain.
  • Live vs apply — mid-run slider changes should apply to the living special immediately (same as Advanced feel).
  • Fair labeling — inspector must show special is using overrides so results aren’t misread.

Recommendation: redesign 0.9.2 as parameterized special + modal. Keep a clear visual mark so you can find them — but mark is the label, not the feature.

2. Goals & non-goals

Goals

  • Exactly one special agent per run (when pop ≥ 1).
  • Special runs on a special param profile (overrides) while the crowd uses global run knobs.
  • Special… modal to edit that profile (lock/sync + per-knob values).
  • Obvious on canvas + inspector shows overrides in use.
  • Optional Focus/pin helpers (convenience only — pin system unchanged).

Non-goals

  • Not a replacement for pin / select / pin-by-ID.
  • Not multi-special or full trait spawn distributions (Phase 1).
  • Not private world rules (spawn interval, food ceiling, map size stay global).
  • Not memory (0.9.3) — but special can get memory first later for demos.
  • Not Lab batch (later); this is one interactive world.

4. Concept

Global run config  →  used by all non-special agents
Special profile    →  used only by the special agent (per-knob or “match world”)

agent.update() resolves each needed scalar via:
  value = agent.isSpecial ? specialProfile.X : global.X
  (or: agent.params.X copied at spawn / when profile changes)

Match world mode (recommended default for each knob or as a master toggle): special mirrors global until you unlock overrides — so Reset doesn’t surprise you with a mutant until you open the modal on purpose.

First draft of this doc treated special as “hero cam only.” That version is superseded. Visual-only special is explicitly out of scope.

5. Parameter model

5.1 Global only (never special-private)

  • Initial agent count, food spawn interval / batch / ceiling
  • Canvas / layout, sim speed, pause
  • World presets that set global hunger/spawn (special profile may stay independent — see §5.4)

5.2 Special-overridable (v1 set) Recommend

Start with movement + personal metabolism — highest demo value for Seek labs.

ParamCrowd source todayWhy special override is fun
Movement policy Global Seek | Random Seek special in a Random world (or reverse) — strongest A/B
Sense radius Global slider Eagle-eyed vs blind seeker
Seek strength Global slider Committed vs lazy seeker
Hunger rate Global Faster/slower personal metabolism
Self-consume / ground eat (relief, amount, threshold) Advanced modal globals Different “stomach” than the crowd

5.3 Optional v1 / easy add

ParamNotes
seekAccel, wanderAmp, maxSpeedAlready exist as globals in code; expose in Special modal only first (or both later).
Starting carried foodSpawn bias for special only on Reset — nice, not required.

5.4 Presets interaction

  • World presets (Lenient / Balanced / Punishing) update globals only.
  • Special profile: either (A) unchanged when world preset fires, or (B) “Reset special to match world” button in modal.
  • Recommend A + explicit Match-all button so experiments aren’t wiped by accident.

5.5 Resolution rule in code

function p(agent, key) {
  if (agent.isSpecial && specialOverrides[key] != null && specialOverrides[key].useCustom)
    return specialOverrides[key].value;
  return globals[key];
}
// In update():
this.hunger += p(this, 'hungerRate');
const policy = p(this, 'movementPolicy');
// ...

Alternative: copy resolved params onto agent when special profile changes or on spawn. Live modal edits must refresh the living special the same tick or next tick.

  • Optional demo preset inside modal later: “Seek loner in Random world” one-click — not required for v1.

7. Visual + focus (secondary)

  • Amber ring on special while alive (identity — still hunger-colored body fill).
  • Select / pin rings keep existing meaning; when pinned special, trends are theirs.
  • Auto pin on Reset — optional; recommend yes so you immediately see special trends when testing overrides.
  • Do not pretend visual-only is the feature.

8. Lifecycle

  1. Reset / startNewRun: spawn crowd → pick one special → apply profile resolution → optional auto pin/select.
  2. Modal edits: update specialOverrides; living special uses new values next physics step.
  3. Special death: profile retained for next Reset or Reroll; pin shows dead; no silent auto-promote.
  4. Reroll body: clear flag on old; set on new living agent; same overrides.
  5. World preset: globals change; special customs persist unless Match-all.

9. Implementation approach

Core work is a param resolution layer + modal, not a second simulation. Refactor just enough of Agent.update() that hunger/move/eat read through a helper instead of bare globals.

9.1 Principles

  1. One resolution function — never scatter if (isSpecial) for every formula; one p(agent, key) (or agent-local copy refreshed from profile).
  2. Crowd path stays default — if not special, identical to 0.9.1 behavior.
  3. Modal is the editor — left rail only gets entry button + maybe compact “3 overrides active”.
  4. Smoke the experiment, not the ring — proof is: Random world + Seek special still homes while crowd dies.
  5. Pin is optional glue — implement focus helpers after params work.

9.2 Suggested build order

  1. Param map + resolver
    Define specialOverrides structure; p(agent, key) falls back to globals.
  2. Wire Agent.update()
    Replace direct hungerRate, movementPolicy, senseRadius, seekStrength, eat knobs (and optional accel/wander/maxSpeed) with p(...). Regression: all custom off → bitwise same feel as 0.9.1.
  3. Pick special on Reset + amber draw + inspector SPECIAL line.
  4. Special… modal — custom toggles + sliders; Match-all; live bind; shared modal manager with Advanced/Help.
  5. Focus / pin / reroll body convenience controls.
  6. Help copy — special vs pin; how overrides work.
  7. Human smoke → freeze 0.9.2-special.

9.4 Killer smoke tests (the real acceptance)

  • All overrides off → special indistinguishable in behavior from crowd (only mark differs)
  • World = Random; special custom Policy = Seek → special paths to food, crowd wanders
  • World = Seek; special custom high hunger rate → special dies faster than peers (same food luck aside)
  • World sense 80; special sense 300 → special notices food others ignore
  • Match all → world clears customs; special behaves like crowd again
  • Advanced world eat knobs still affect crowd; special custom stomach independent when enabled
  • Pin still works on special and on non-special

11. Acceptance

  • Special is not merely a second pin — params can differ and change outcomes
  • Special… modal edits overrides; Match-all restores world parity
  • Crowd still driven only by global controls / Advanced
  • Pin/select unchanged in role; can pin special or others
  • At least one dramatic A/B works (Seek special in Random world)
  • Help explains special vs pin
  • VERSION 0.9.2-special when frozen; no Lab/memory scope creep
