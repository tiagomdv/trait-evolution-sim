1. Goal

Replace (or grow) the slim All history… experience into a Run logs desk:

  • See many finished runs at once in a wide modal
  • Compare outcomes and (where useful) knobs by eye
  • Export last / Export all as JSON download
  • Cheap extras: Copy last / Copy all to clipboard; sensible filenames
Important split: what you see in the table can be compact. What you export in the file should still include the full knob snapshot + metrics. Options A/B/C only change the on-screen table layout, not the richness of the JSON.

2. A vs B vs C in one sentence each

Recommended v1

Option A — Core columns + detail

Table shows ~10 comparison columns. Click a row → side (or bottom) panel lists all knobs for that run.

Usually avoid

Option B — Every knob is a column

One huge spreadsheet: hunger rate, sense, seek, eat knobs… all as columns. Horizontal scroll forever.

Later polish

Option C — Toggle Wide / Compact

Same modal can switch: Compact ≈ A’s table only; Wide ≈ B’s full columns. Extra UI work.

Same data under the hood (knobs + metrics stored per run) Option A [ # Pre Pol N Dur Long Dead … ] + [ detail panel: all knobs ] Option B [ # Pre Pol N Dur … hungerRate senseRadius seekStrength … many more → scroll → ] Option C [ Compact | Wide ] toggle switches between A-like and B-like tables

4. Option A — Core columns + row detail (recommended)

How it works

  1. Table shows only columns you need for quick A/B (policy, preset, survival outcomes).
  2. Click a row → it highlights → detail panel shows every knob for that run.
  3. Export always writes full knobs + metrics to JSON (not just visible columns).

Core columns (v1 proposal)

ColumnMeaningWhy in the grid
#Run numberIdentity
Prelenient / balanced / punishing / customDifficulty ladder
Polseek / randomMain behavioral A/B
NInitial agentsSetup size
DurRun duration (s)How long the world lasted
LongLongest agent life (s)Lucky survivor signal
DeadStarvation deathsHardness
FinFinal populationRemnant or wipe
Hung / FoodRun averagesFeel of scarcity
Endextinction / resetHow the run closed

Detail panel fields

Everything else: hunger + eat advanced + sense/seek/wander/maxSpeed + food spawn + version string. Optional later: special overrides block.

Pros / cons

ProsCons
  • Readable on laptop
  • Matches “scan then drill in”
  • Easy Track A layout
  • Detail can grow without wrecking the table
  • Can’t eyeball 3 runs’ senseRadius side-by-side without clicking each
  • Needs click affordance (selected row style)

5. Option B — Every knob is a column

How it works

One table. Outcomes and every parameter each get a column. No detail panel required.

Pros / cons

ProsCons
  • True spreadsheet: sort/compare any knob across runs in theory
  • One mental model (“it’s all rows”)
  • Horizontal scroll hell on real screens
  • Tiny truncated headers
  • Most knobs identical across runs (noise)
  • Harder to style; more DOM
Usually not v1. Export JSON already gives you the spreadsheet offline (paste into Sheets/Excel). The in-app UI does not need to be Excel.

6. Option C — Compact / Wide toggle

How it works

Toolbar control: Compact (A-like core columns; detail optional) vs Wide (B-like full columns). Export buttons unchanged.

Pros / cons

ProsCons
  • Best of both for power users
  • Can ship Compact first, Wide later
  • Two table renderers to maintain
  • Extra chrome + state
  • Wide mode still has B’s readability problems
Process suggestion: implement A for 0.9.4-export. If you later find yourself exporting just to compare one knob in a sheet every day, add Wide (C) as a follow-up — don’t block export on it.

7. Export actions + cheap extras

ControlBehaviorv1?
Export last Download one JSON object (newest finished run). Filename e.g. tes-run-12-0.9.3-vision.json yes
Export all Download JSON array of all session runs. Filename e.g. tes-session-3runs-0.9.3-vision.json yes
Copy last Same payload as Export last → clipboard (toast: “Copied”) yes · cheap
Copy all Same payload as Export all → clipboard yes · cheap
Disable when empty If runHistory.length === 0, export/copy buttons disabled or no-op with hint yes
Export selected row Optional: export the highlighted run instead of “last” nice later
Prefer pretty-printed JSON (JSON.stringify(data, null, 2)) so pasting into notes is human-readable.

8. JSON schema (v1 sketch)

Illustrative. Field names can match existing recordCurrentRun() keys where possible. Lab can reuse this row shape later.

{ "version": "0.9.3-vision", "exportedAt": "2026-08-06T15:00:00.000Z", "run": 12, "knobs": { "preset": "balanced", "movementPolicy": "seek", "numAgents": 40, "hungerRate": 0.065, "foodSpawnInterval": 10, "senseRadius": 180, "seekStrength": 1.0, "seekAccel": 0.35, "wanderAmp": 0.5, "maxSpeed": 2.0, "selfConsumeRelief": 1.0, "groundEatRelief": 1.7, "selfConsumeThreshold": 12, "selfConsumeAmount": 0.75 }, "outcomes": { "durationSec": 85, "longestSec": 72, "finalPop": 2, "deaths": 38, "avgPop": 18, "avgHunger": 14.2, "avgFood": 1.1, "endedBy": "extinction" } }

Export all = JSON array of these objects (or { "version", "runs": [ … ] } wrapper — human picks at implement time; wrapper is slightly nicer for metadata).

Data plumbing required: today’s history rows do not store full knobs. On recordCurrentRun(), snapshot live world params into the history object (no agent behavior change).

9. Entry point & chrome

ChoiceRecommendation
Open from Grow All history… into Run logs… (same place in History dock). Avoid a second nearly identical modal.
Modal size Large: ~min(960px, 92vw) wide · ~min(70vh, 640px) tall body; table scrolls inside.
History dock Keep last-3 compact strip for glance; full science lives in the modal.
Special agent knobs Out of v1 table unless cheap; optional block in detail later.

10. Scope / non-goals

In scope (0.9.4-export)

  • Large Run logs modal
  • Option A layout (unless human picks B/C)
  • Knob snapshot on record
  • Export last / all (download)
  • Copy last / all (clipboard)
  • VERSION + archive + docs ritual

Out of scope

  • Lab mode / N headless runs
  • Seeded RNG (can follow if wanted)
  • CSV (JSON first)
  • Server / cloud save
  • Sorting/filtering spreadsheet features
  • Memory mechanic

11. Decision checklist (for the human)

  • Pick layout: A (recommended) / B / C
  • Confirm cheap extras: Copy last + Copy all = yes
  • Confirm entry: evolve All history… → Run logs…
  • Confirm JSON: pretty-print; single object vs array for “all”
  • Special overrides in v1 detail? default no
  • Codename: 0.9.4-export (or 0.9.4-run-logs)
Default recommendation if undecided: Option A + Export last/all + Copy last/all + grow All history into Run logs. Ship as Track A with light history-record plumbing. No full design rework needed beyond this doc.
