1. Goals & non-goals

Goals

  • No document scrollbar — app fills the viewport; only panels scroll inside.
  • Clearer header hierarchy — title / phase / version vs Speed · Pause · Reset.
  • Movement policy first-class — Seek | Random easy to find and toggle.
  • Breathing room before the Speed group.
  • Presets stay visible with a strong active state, and retune Lenient / Balanced / Punishing for a Seek-default world.
  • Advanced out of the rail — modal so basic controls stay scannable.
  • Calmer version badge — full codename, quiet styling.
  • In-app Help / glossary — one popup that explains parameters, metrics, modes, and presets (not a separate docs site).

Non-goals

  • No rewrite of the seek algorithm, eat rules, or food ceiling logic (Track B mechanics stay frozen).
  • No slide drawers (deferred).
  • No special agent / memory (later 0.9.x).
  • No redesign of Trends / History content structure.
  • No new source files — single index.html.
  • No per-control floating tooltips-only solution (glossary modal is the primary help surface; optional tiny “?” later).
Track A (+ light feel) — chrome, preset numbers, and help copy may ship together in 0.9.1-ui-chrome. Seek pathing math stays as frozen in 0.9.0-seek. Versioning option B: archive freeze when accepted.

3. Design principles

  1. Viewport is the product — normal desktop lab should not scroll the whole page.
  2. Primary vs secondary — Pause / Reset / Speed are primary; version is metadata; Advanced is secondary.
  3. Mode before fine-tune — Seek | Random is a run mode; sense + seek strength stay next to it; rare knobs go Advanced.
  4. Same visual language — reuse .btn-speed / .on for policy and presets.
  5. Don’t punish Seek labs — presets stay for extreme hunger / food A/B, retuned so the ladder still means something under Seek.
  6. Explain once, in place — one Help modal beats scattering long labels on every slider.

4. No page scroll (viewport lock)

Target CSS behavior

  • html, body: height: 100%, overflow: hidden
  • .app-shell: height: 100vh, overflow: hidden, border-box
  • Header: flex-shrink: 0; prefer single row on wide screens
  • .app-body: flex: 1; min-height: 0; overflow: hidden
  • Only .col-panel / history / trends: overflow: auto

Scroll acceptance

  • ~1280×800 and 1440×900: no page vertical scrollbar
  • Long left controls: scroll only inside left panel
  • Long history: scroll only inside history list
  • Resize still calls afterLayoutChange / canvas fit

If the header wraps on narrow widths, still keep shell at 100vh and body overflow hidden — columns get shorter (min-height: 0), not a body scroll.

8. Presets — keep, highlight, and retune

Presets are the three buttons Lenient / Balanced / Punishing. They set several knobs at once so you can jump to a known “difficulty” for Seek labs without dragging every slider.

Decisions Locked

Question What it means This slice
Keep or hide the buttons? Do the three preset buttons stay on the left rail? Keep visible
Active highlight? Can you see which preset is current (like speed 1× is lit)? Yes — .on style + sync
Change the numbers? When you click a preset, should hunger / spawn / advanced eat values differ from today’s pre-Seek table? Yes — retune now
In short: keep the three buttons, light the active one, clear to “custom” when you drag a linked slider, and rewrite the preset value table so the ladder fits a Seek-default world.

What a preset sets

Same fields as today in applyPreset() — retune the values, not the field list (unless smoke shows a gap).

  • Hunger rate, food spawn interval
  • Advanced eat knobs: self-consume relief / amount / threshold, ground eat relief
  • Does not force movement policy (Seek stays default unless human toggles Random)
  • Does not have to touch sense radius / seek strength unless we add them to the table during implement (optional; default leave movement knobs alone so A/B policy stays clean)

Retune intent (Seek-default ladder)

Old numbers were written when agents mostly random-walked. With Seek, agents find food more often — so “Balanced” can feel too soft, and the gap between tiers can feel wrong.

Preset Lab intent Feel target (under default Seek)
Lenient Warm-up / demo / “is Seek working?” Most agents survive a long run; deaths rare unless you force Random.
Balanced Default interesting lab Noticeable pressure; a large living majority early, clear attrition over a full run — not a wipe, not a petting zoo.
Punishing Harsh stress test Only skilled Seek + good sense/spawn luck keeps a remnant; Random dies fast. Still playable (not instant extinction at tick 10).

Starting value sketch (implement + human smoke; not sacred)

Current freeze for reference: Lenient ≈ hunger 0.03 / spawn 5 · Balanced 0.05 / 8 · Punishing 0.09 / 12 (plus advanced eat fields). Spawn slider now goes 1–50; presets can use that range.

Knob Lenient (easier) Balanced Punishing (harder)
Hunger rate ↓ slightly or hold soft near current mid ↑ harsher than old 0.09 if Seek makes mid too easy
Food spawn interval ↓ (food more often) mid ↑ (food rarer; still ≥1)
Ground / self-consume relief more forgiving mid stingier relief / higher self-consume threshold
Process: pick concrete numbers in implement, smoke under Seek and Random, then lock the table when the three intents above feel right. Document final numbers in IMPLEMENTATION_LOG when shipping — design keeps intent, not a frozen spreadsheet.

UI behavior to wire

  • Applying a preset → that button gets .on; clear the others; sync all affected sliders + labels.
  • Any related slider moves → currentPreset = 'custom' and clear all preset .on.
  • Prefer scrolling the left panel over removing presets if the rail is tall.

10. Help / glossary — explain metrics & parameters

Lab knobs and KPI labels are jargon. Instead of packing long text into the left rail, ship a single Help surface: a scrollable popup glossary of parameters, modes, presets, and metrics.

Entry point Recommended

OptionWhereNotes
A · Left rail (preferred) Quiet text button Help / glossary next to or under Advanced… Keeps header clean; near the knobs people ask about.
B · Header Small ? or Help before Speed group Fine if rail is crowded; use only one of A or B.
Not this slice: individual hover tooltips on every slider as the main solution (optional later). One glossary modal is enough for 0.9.1.

Modal behavior

  • Same chrome as Advanced: dim overlay, ✕, click-outside, Escape.
  • Wider than Advanced — about 480–560px max-width; max-height ~70vh; scroll inside.
  • Does not pause the sim automatically.
  • Only one modal open at a time (opening Help closes Advanced and vice versa).
  • Static copy in index.html (no external fetch, no new files).

Content structure (sections inside the modal)

SectionEntries (explain each)
Modes Seek — steer toward nearest food in sense radius; blend scales with hunger × seek strength.
Random — pre-0.9 wander baseline for A/B (“does Seek actually help?”).
Basic parameters Initial agents · Hunger rate · Food spawn interval · Sense radius · Seek strength — one short plain-language line each (what it does + “higher means …”).
Presets Lenient / Balanced / Punishing intents from §8 (warm-up · default lab · stress test). Note that presets set multiple knobs and do not change Seek|Random by themselves.
Advanced parameters Self-consume relief, amount, threshold · Ground eat relief — when agents eat carried food vs ground pellets and how hunger drops.
Live metrics (KPI dock) Living / dead counts, avg hunger, min/max carried food (not hunger min/max), tick / timing as shown — one line each: definition + how to read it in a lab.
Inspector fields Per-agent: hunger, carried food, policy-related fields (seek blend, dist→food), pin notes if present.
Run history (short) What “preset”, duration, survivors mean on a finished run row — enough to read History without guessing.

Copy style

  • Plain language first; code names in parentheses only if useful.
  • 1–3 sentences per entry — not a design essay.
  • Prefer “Higher hunger rate → agents starve faster” over formula dumps (short formula OK on Advanced entries).

13. Implementation steps

  1. CSS viewport lock — html/body overflow, shell overflow, flex min-height: 0.
  2. Header — quiet full-codename badge; extra space before speed group.
  3. Controls structure — Run size → Environment → Movement (policy + basic sliders) → Presets → Advanced + Help buttons.
  4. Presets — syncPresetButtons() + CSS .btn-preset.on + retune applyPreset() value table to §8 intents.
  5. Advanced modal — markup + open/close; move advanced hunger sliders in; remove old accordion.
  6. Help / glossary modal — shared modal shell; sectioned static copy for modes, params, metrics, etc.
  7. Smoke §14 (Seek ladder under each preset + Help open/close) → bump VERSION → archive + MANIFEST + LOG (include final preset table) → remove open item from FUTURE_FEATURES.

Do not rewrite seek pathing / eat rules. Preset number changes and help copy are in scope.

14. Acceptance

  • No page vertical scrollbar at 1280×800 / 1440×900 with default columns.
  • Left panel scrolls independently when content is long.
  • Basic sliders visible on rail: agents, hunger rate, food spawn, sense radius, seek strength.
  • Seek | Random obvious; active state clear; still changes movement live.
  • Speed group has visible separation from the title / phase / badge cluster.
  • Active preset clearly highlighted; dragging a preset-linked slider clears highlight to custom.
  • Presets retuned: Lenient / Balanced / Punishing feel distinct under default Seek (intents in §8).
  • Advanced modal opens / closes; advanced sliders still live-bind.
  • Help modal opens / closes; covers modes, basic + advanced params, presets, KPI metrics, inspector (and short history notes).
  • Only one of Advanced / Help open at a time; Escape closes.
  • Version badge quieter; full codename; matches VERSION.
  • Seek regression: short run still paths to food under Seek (no accidental policy break).
  • Hide left / right columns + canvas resize still work.
