0.9.0-forage — design

Environment-responsive foraging movement for trait-evolution-sim. Replaces pure random walk as the default agent locomotion so hunger and food on the map drive visible, analyzable behavior — without yet introducing the full Phase 1 trait system.

1. Goals & non-goals

Goals

  • Replace pure Brownian motion as the default movement so agents respond to the environment (food locations) and internal state (hunger).
  • Make survival readable: starving agents look purposeful; paths toward food are obvious when watching the canvas or a pinned agent.
  • Keep residual randomness so runs remain diverse and “lucky survivor” dynamics do not vanish entirely.
  • Build a behavior foundation for Phase 1: expose knobs (sense range, seek strength, wander noise, optional greed) that traits can later modulate without rewriting the engine.
  • Stay Phase 0: no inheritance, no reproduction, no full trait UI/distributions yet.
  • Stay single-file: all changes in live index.html (+ VERSION / archive / docs ritual).

Non-goals (explicitly out of 0.9.0)

  • Full trait system (HoardingBias, ExplorationRate, TradeBoldness as first-class Phase 1 features).
  • A* / grid pathfinding, flocking, multi-resource utility AI, neural nets.
  • Automatic ML parameter search / Bayesian optimization of presets.
  • Layout chrome work (already shipped 0.8.x Track A).
  • Silent changes to hunger rates, eat relief, or death threshold “while fixing movement” without labeling them and human tuning.
Track classification: Track B · Mechanics Human leads sensibility and browser feel. AI may propose patches or implement under explicit supervision per AGENTS.md. This document is the design gate before implementation.

3. Problem statement

Random walk made sense for the first hunger sandbox: prove starvation, sliders, and observability. It is a weak base for everything that follows:

  • Observability story is thin: survival is mostly luck of paths crossing food, not readable policy.
  • Traits have nothing meaningful to modulate if movement ignores the world.
  • User intent (session 2026-07-15): agents should path based on environment; always looking for food; later greed/hoarding and population analysis (high vs low greed under the same food regime).

Design thesis: The interesting story is not whether agents seek food — it is how hard, with how much noise, and (later) when they stop taking more (greed). 0.9.0 proves the foraging engine; Phase 1 makes personality first-class.

4. Core concepts

ConceptMeaning in 0.9.0
Seek Steering velocity component toward a chosen food target (usually nearest in range).
Wander / noise Residual random acceleration (legacy walk), so paths are not perfect and exploration continues.
Sense radius Max distance at which an agent can “see” food for seeking. Outside range → pure wander (or last-memory later).
Seek blend How much of the velocity update is seek vs wander; scaled primarily by hunger in MVP.
Greed (optional) Extra seek / pick-up appetite when not starving. Not full HoardingBias trait UI in MVP — see §8.
Movement policy Run-level mode: at least Seek (default). Optional Random retained for A/B science.

Two drives (mental model for later traits)

DriveRoleIn 0.9.0 MVPIn Phase 1+
Hunger Urgency: life-or-death steering toward food Primary scaler of seek blend May be modulated by traits / thresholds
Greed / HoardingBias Appetite for surplus when comfortable Optional global or per-agent scalar only Real trait + UI + distributions + analysis panels

  • Default movement policy: hunger-weighted seek nearest food + residual noise.
  • Configurable: sense radius, seek strength, wander strength, max speed (reuse or rename existing cap).
  • Fallback when no food in sense radius: wander only (current-style noise).
  • Run-level toggle or preset-friendly switch: Random vs Seek (default Seek) for scientific A/B.
  • VERSION / UI badge / archive / MANIFEST / IMPLEMENTATION_LOG / FUTURE_FEATURES (remove open forage item when shipped).
  • Smoke criteria in §16 met under human browser testing.

5.2 Should ship if cheap

  • Inspector fields: target food distance, current seek blend, (if enabled) greed.
  • Optional short heading tick or 4–8 point trail on selected/pinned agent only (performance-safe).
  • One metrics row: e.g. mean distance-to-nearest-food among living agents (optional).

5.3 Nice-to-have / stretch (same PR only if human wants)

  • Per-agent random greed ∈ [0,1] without full trait system + color by greed.
  • Global “greed strength” slider under Advanced.
  • Survivor vs dead avg greed / avg food split (only if greed exists).

5.4 Explicitly deferred

  • Memory / last-good food patch return (bridge to ExplorationRate).
  • Food density gradient (soft field) instead of nearest point target.
  • Cohort lab mode (half high / half low greed spawn).
  • Auto-discovered “best presets” from grid search (Tier 2–3 in §11).
  • Slide drawers UI (Track A, separate).

6. Movement algorithm (normative)

Replace the locomotion block inside Agent.update() (or extract steer(agent) for clarity). Eating, death, and self-consume stay as separate steps unless noted.

6.1 Recommended default: nearest-food seek + hunger blend

// Per agent, each tick (conceptual pseudocode)

// 1) Find target
target = null
bestD2 = senseRadius * senseRadius
for each food f with f.amount > ε:
  d2 = dist²(agent, f)
  if d2 < bestD2:
    bestD2 = d2
    target = f

// 2) Desired seek direction (unit vector), or zero if no target
if target:
  desired = normalize(target.pos - agent.pos)
else:
  desired = (0, 0)

// 3) Hunger-scaled blend in [0, 1]
//    u = 0 when satiated, → 1 when starving
u = clamp(agent.hunger / hungerRef, 0, 1)   // hungerRef default 100 (death threshold)
// optional soft knee: u = smoothstep(hungerStart, hungerRef, agent.hunger)
blend = u * seekStrength                     // seekStrength default ~0.7–1.0, clamp blend to [0,1]

// 4) Optional greed (if enabled): raise floor of blend when not starving
// blend = max(blend, greed * greedSeekFloor)

// 5) Wander kick (legacy)
wander = ((rand-0.5)*wanderAmp, (rand-0.5)*wanderAmp)

// 6) Integrate velocity
seekVel = desired * maxSpeed                 // or desired * seekAccel then integrate
agent.vx += lerp(wander.x, seekVel.x - agent.vx, blend) * …  
// SIMPLER recommended form:
agent.vx = agent.vx * damping + wander.x + blend * desired.x * seekAccel
agent.vy = agent.vy * damping + wander.y + blend * desired.y * seekAccel
// then clamp speed to maxSpeed

// 7) Position + wrap (unchanged)
Implementation note: Prefer a simple form that is easy to tune in-browser: 
// Suggested concrete MVP (easy to port)
const w = wanderAmp; // e.g. 0.5 (today’s jitter)
let ax = (Math.random() - 0.5) * w;
let ay = (Math.random() - 0.5) * w;

const blend = Math.min(1, (this.hunger / 100) * seekStrength);
const t = nearestFoodInRadius(this, senseRadius);
if (t && blend > 0) {
  const dx = t.x - this.x, dy = t.y - this.y;
  const len = Math.hypot(dx, dy) || 1;
  ax += blend * seekAccel * (dx / len);
  ay += blend * seekAccel * (dy / len);
}
this.vx += ax; this.vy += ay;
// clamp speed to maxSpeed; then x+=vx; y+=vy; wrap
Exact constant names can match existing style (lets + sliders). Values in §7 are starting points for human tuning.

6.2 Policy: Random vs Seek

PolicyBehaviorUse
random Current 0.8.4 walk only (jitter + speed cap). Ignore food for steering. Baseline A/B; regression; “luck” demos
seek (default) §6.1 algorithm Normal play; Phase 1 readiness
gradient (optional later) Steer toward higher local food density in radius R, not a single pellet Softer herds; deferred unless MVP feels too “laser guided”

6.3 Target selection rules

  • Default: nearest food by Euclidean distance among pellets with amount > ε (e.g. 0.2, same as eat eligibility).
  • Ties: first in array order is fine (deterministic enough for this sim).
  • Empty world / none in radius: wander only; do not retain a stale target across ticks unless memory feature is added later.
  • Do not require line-of-sight or collision with other agents (agents already overlap freely).

6.4 Edge wrap interaction

World wraps. Nearest-food on a torus is more correct but more code. MVP decision: use non-toroidal nearest food (screen-straight distance). Document that agents near edges may seek “the long way.” Optional follow-up: toroidal minimum-image distance if wrap artifacts look silly in testing.

7.2 UI placement (Track A-friendly, no layout rewrite)

  • Controls column under environment/hunger: section “Movement”.
  • Policy: two or three small buttons (Random / Seek), same pattern as speed buttons.
  • Sliders: sense radius, seek strength, wander (Advanced collapse OK for seekAccel if crowded).
  • Do not reintroduce old sidebar tabs; stay in Tall Command docks.
  • Version badge → v0.9.0-forage; phase label remains Phase 0 · Survive.

7.3 Interaction with existing presets

  • Lenient / Balanced / Punishing today set hunger & food spawn — keep that.
  • When applying a preset, either (a) leave movement params unchanged, or (b) set documented movement defaults per preset later (“Greed lab” etc.). MVP: (a) is fine.
  • Reset / new run: re-roll agent positions; if per-agent greed exists, re-sample greed on new agents.

8. Greed / heterogeneity (optional in 0.9)

User desire (2026-07-15): always looking for food; hunger + hoarding/greed; compare high vs low greed population outcomes.

8.1 Why not full HoardingBias in 0.9.0

  • If greed is the star of 0.9 with full trait UX, Phase 1 becomes a rename.
  • 0.9 should prove the foraging engine; Phase 1 should introduce the trait product (distributions, inspector semantics, later inheritance).

8.2 Allowed compromises in 0.9

OptionDescriptionRecommendation
A. None Hunger-only blend; all agents identical policy Cleanest MVP
B. Global greed slider One run-level scalar adds seek floor when hunger low Good middle ground
C. Per-agent greed random greed = U[0,1] at spawn; no trait UI; optional color; basic survivor stats Best preview of “science” without Phase 1 ceremony

Human decision: pick A, B, or C before implementation. Default recommendation if undecided: A for first PR, then C in a fast follow if forage feel is good.

8.3 If C is chosen — behavioral effect

  • High hunger → seek dominated by hunger (greed less visible).
  • Low hunger + high greed → still steers toward food, keeps stacking inventory.
  • Low hunger + low greed → weaker seek, more wander, smaller piles.
  • Ground eat rule can stay shared; greed primarily affects steering, not a second physics.
  • Optional later: greed slightly increases willingness to move toward food even when inventory high (same blend floor).

16. Acceptance / smoke criteria

  • Policy Seek (default): hungry agents visibly curve toward nearby food pellets.
  • Policy Random: behavior matches pre-0.9 locomotion qualitatively (jitter walk).
  • With food depleted in sense range, agents wander (no NaN, no stuck freeze).
  • Death, self-consume, ground eat, food respawn still function.
  • Pause / resume / speed 1×–10×; trends and pin graphs still update.
  • Reset / new run safe; no residual target bugs across runs.
  • UI version string matches VERSION file.
  • Archive snapshot + MANIFEST updated for the release.
  • Human judges sim “feel” acceptable under Balanced preset (Track B gate).
