Not a modal. Not lab.html. Lab is a full in-app mode inside the same index.html: header stays; body swaps World (canvas + rails) for Lab (experiment desk). Toggle World | Lab in the header (see naming §1b).

1b. Naming — “Play” is weak

Play sounds like a toy / pause-button twin. Lab is the experiment desk; the canvas mode is the living world.

LabelProsCons
World | Lab Recommended Clear spatial sim; matches Survive sandbox; pairs well with Lab Slightly abstract
Live | Lab Emphasizes real-time canvas; short “Live” can mean streaming elsewhere
Sim | Lab Technical, accurate Dry; Lab is also a sim
Watch | Lab Observability vibe Passive; you also tune knobs
Play | Lab Familiar from games Under-sells science product; easy to confuse with Pause
Design default: header toggle World | Lab. Copy elsewhere: “World mode” = canvas + rails; “Lab mode” = headless batch desk. Human can still pick Live if preferred before implement.

2. Goal

World = live canvas (optional multi-group + special agent). Lab = headless multi-setup batch (crowd only).

  • 1–5 crowd setups; agents split agents / setups
  • Lab: R runs × setups; stop when; result cards; Export / Copy last batch only
  • No special in Lab; no graphs v1
  • Parameters modal = setups only (+ batch meta); full knobs per setup

3. Setups (1–5) — not “A vs B only”

In Parameters… you maintain a list of crowd setups (min 1, max 5). Add / remove setups (cannot remove the last one). Each setup has the full world knob set. Example: 2 setups → classic compare. 5 setups → five different packs in one batch.
SettingWhereMeaning
SetupsParameters modal1–5 named packs (Setup 1…Setup 5)
Agents per worldParametersTotal agents in each simulated world (e.g. 100)
Group sizeDerivedagents / setups (e.g. 100/2=50, 100/5=20)
Runs per setupParametersHow many headless worlds Lab runs for each setup (e.g. 50)
Total Lab runsDerivedruns_per_setup × number_of_setups
Example agents = 100 · setups = 2 · runs/setup = 50 · World view: 50 agents use Setup 1 knobs, 50 use Setup 2 knobs · Lab: 50 full worlds of Setup 1 + 50 full worlds of Setup 2 = 100 headless runs agents = 100 · setups = 5 · runs/setup = 20 · World: 20 agents per setup · Lab: 20×5 = 100 headless runs

No hard-coded “Seek vs Random” mode — that is just two setups that differ on policy.

2b. World vs Lab — who does what

WorldLab
Job Watch one live sim; feel, pin, special agent demos Measure many headless runs of crowd setups
Setups 1–5 Optional: multi-group spawn (agents split by setup) for visual A/B/… Core: N runs per setup, result cards, export
Special agent Yes — existing Special… popup; one marked agent vs crowd (default or multi-group) No — not in Lab batch, not in Lab Parameters, not in Lab results
Why split Special is a “pet / probe” for live observation Lab is clean multi-config science; special would muddy group stats
Human lock: remove special entirely from Lab UI and Lab runner. To study special vs a config, use World mode (special on + crowd knobs / multi-group).

5. Left column — values + buttons (always Parameters…)

  • No sliders on the left — summary values + Parameters… / Start.
  • Each setup summary (same as earlier design-doc style): difficulty, policy, sense · str · accel, hunger · spawn.
  • Special summary: enabled + sense · str (when on).
  • Result cards: same config summary + outcomes (alive/dead, avgs, special stats if on).
  • Full Advanced eat knobs live only in the Parameters modal.
  • Stop when = value from Parameters (not left buttons).

6. Parameters modal (Lab) — setups only

Opens from left Parameters…. Tabs = Setup 1 … Setup k (dynamic, 1–5) plus a small Batch area (or first tab section).

  • Each setup: difficulty + full crowd knobs (movement, env, eat) — same set as World rails + Advanced
  • + Add setup / remove (min 1, max 5)
  • Batch: agents per world, runs per setup, stop when
  • No Special tab in Lab Parameters — special is World-only
  • Done → left summaries refresh

7. World multi-group + special (World only)

Optional: spawn agents split evenly across the same 1–5 setups used by Lab (visual compare).

Special agent remains the existing World Special… popup — one marked agent vs the live crowd (default single group or multi-group). That is how you “test special against a config,” not via Lab batch.

8. Stop rules (Lab batch)

Set in Parameters → Batch; shown as a value on the left (not buttons).

Stop whenMeaning
All deadPopulation 0 (extinction)
Max time (recommended safety)Hard cap in sim-seconds/ticks so a run cannot hang

Special-dies / only-special-left stop rules are World/special concerns — out of Lab once special is removed from Lab.

9. Progress bar

  • Determinate bar: completed / total (e.g. 34 / 100)
  • Label current side: Setup A or Setup B
  • Sticky top of right pane · Cancel · optional shimmer while a trial is long

9. After the batch

Last batch only. No history. Per-setup result cards: alive/dead (avg end), mean duration, avg hunger, avg food. Actions: Export · Copy all only (Start stays on the left). No graphs. No special rows.

11. Trial record & export

Reuse spirit of 0.9.4-run-logs envelope:

{ "version": "0.9.5-lab", "exportedAt": "…", "mode": "lab", "experiment": { "mode": "A-vs-B", "runsPerSide": 50, "agentsPerWorld": 100, "setupA": { "knobs": {…}, "special": {…} }, "setupB": { "knobs": {…}, "special": null }, "endRule": "extinction", "specialEnabled": false, "baseKnobs": { … }, "vary": { "movementPolicy": ["seek", "random"] } }, "runs": [ { "run": 1, "seed": 101, "cell": { "movementPolicy": "seek" }, "knobs": { … }, "special": null, "outcomes": { "durationSec": 88, "deaths": 91, "finalPop": 9, "endedBy": "extinction", "specialLifeSec": null, "specialAliveAtEnd": null } } ] }

Per-trial fields should stay close to Play run logs so Grok analysis and future Playbook stay consistent.

New-session implementation guide

For the next chat / implementer: read this whole design HTML first, then AGENTS.md, live VERSION / index.html. Do not bump VERSION until the human asks. Lab = crowd multi-setup only; special stays World.

Product locks (do not re-litigate)

  • Mode names: World | Lab (not Play)
  • Shell: full body swap in one index.html
  • Header control: match existing Seek|Random button style, prefer center of header
  • Lab setups: 1–5, add/remove; agents split evenly; R runs per setup
  • No special agent in Lab (UI, runner, export, stop rules)
  • Special remains World Special… for live probing
  • Left Lab column: value summaries only + Parameters… + Start
  • Stop when: set in Parameters, displayed as value on left
  • After batch: result cards + Export + Copy all; last batch only; no graphs; no history

Phase 0 — UI shell (check with human before mechanics)

  1. World | Lab toggle; show/hide #view-world / #view-lab; pause World on Lab enter
  2. Lab left layout (batch summary + setup summaries as in mocks)
  3. Parameters modal: Setup 1…k tabs, add/remove, Batch fields; no Special tab
  4. Fake “batch complete” cards for 2/4/5 setups (static data) so human can judge density
  5. Export/Copy buttons present (can no-op until Phase 3)

Gate: human says UI OK before Phase 1.

Phase 1 — Parameter model

  1. labSetups[] full knob objects; batch meta {agents, runsPerSetup, stopWhen}
  2. Bind modal ↔ model; re-render left as values only
  3. agentsPerGroup = floor(agents / setups.length)

Phase 2 — Headless engine

  1. Seeded RNG + runOneHeadless(setupKnobs, seed, stopWhen) → metrics
  2. No special path in Lab runner
  3. Max-ticks safety always

Phase 3 — Batch + export

  1. For each setup × R: progress bar, cancel
  2. Aggregate metrics → cards (alive/dead, duration, avgs)
  3. Last-batch store; Export download + Copy all JSON; overwrite on new Start

Phase 4 — World multi-group (optional same version)

  1. Optional: spawn groups from same setups for visual compare
  2. Keep World Special… independent of Lab
